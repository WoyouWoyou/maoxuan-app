# 四象限工作法

入口固定在左侧栏底部、原文书库上方；侧栏收起时保留四格图标。数字为全部来源中未完成、且已经纳入待办的行动数。

## 视图与详情

- 四象限与 Todo 清单展示相同的行动，可以切换；记住上次使用的视图。
- 四象限分别为立即行动、计划安排、协调处理、减少投入。历史行动和未指定象限的新行动进入待归类，截止日不用于推断重要性。
- Todo 按逾期、今天、接下来、未安排日期、已完成分组。同一截止日优先展示重要行动。
- 支持来源、关键词、象限、今天及已完成筛选；今天包含需要处理的逾期行动。
- 点击任务打开右侧详情：任务名称、来源问题、象限、截止日与时间、行动目的、完成标准、进展记录、完成/恢复。编辑文字失焦保存，进展明确提交后保存。
- 手动添加需要关联一个问题，任务直接写入原问题的行动清单；关联到毛选工作台时，创建动作本身即视为执行承诺，任务直接出现在清单里。
- 窄桌面窗口下详情固定靠右、主区改为纵向排列，详情内容独立滚动，完成按钮固定可见。

## 数据与一致性

不复制任务，不建立第二份任务状态。阅读法使用 `SessionData.actions`，工作法使用 `SessionData.workbench.actions`。聚合标识为会话 id + 行动 id，避免不同问题使用相同行动 id 时冲突。

工作台行动有两个独立字段：`planningState`（candidate / queued，是否被用户纳入工作清单）和 `status`（todo / done / dropped，执行结果）。模型生成和第四步手工新增只产生候选；只有 `planningState === 'queued'` 的工作台行动进入工作清单、四象限、侧栏计数和 AI 自动分类。候选只在工作台第四步可见，不能完成、放弃或记录进展；“移回候选”只允许未完成、未放弃且没有阶段记录的行动。纳入与撤回通过 `enqueueActions` / `returnActionsToCandidates` 显式命令批量提交，一次提交对应一个事务和一份版本快照，任何一条不合法都会整批失败。

包含进行中和已归档问题的行动；回收站的问题、已放弃的行动和未纳入的候选不出现在待办中。每条行动保留来源，支持回到原问题。

阅读行动新增可选的 quadrant、purpose、verify；工作行动新增可选的 quadrant、dueDate 以及必填的 planningState。会话 JSON 的 v2 → v3 迁移把全部旧工作台行动标记为 `queued`，保留原有执行状态和阶段记录；升级不会自动清空待办，用户可以在第四步把尚未开始的行动主动移回候选。现有严格状态与 IPC 校验同时扩展，原问题中的编辑不会删除规划字段。

所有修改通过既有 reading.apply / wb.apply 命令写入 SQLite，并写入版本快照。写入前重新读取原问题，在串行队列中基于最新数据构造命令；由 stateVersion 拒绝外部并发冲突，界面显示错误并重新加载，不覆盖无关的来源、周期、验收、结果和进展字段。加入待办失败时保留本次勾选，可用同一个 mutationId 原样重试；并发冲突则刷新服务端状态并要求重新核对选择，不自动重发旧意图。批量命令只带行动 ID、不带文本：编辑表单有未保存修改时，批量操作栏禁用并提示“请先保存或取消编辑”，提交函数内再拦一次，避免把库里的旧文本当成刚筛过的修订推送出去。

当前窗口的 sessions-changed 立即刷新聚合；重新聚焦和 15 秒轮询补齐其他窗口的变更。标题、目的与完成标准不调用 AI。

## 验证

`tests/actions.test.ts` 覆盖双来源聚合、归档/回收站、跨会话重复 id、待归类、规划字段、完成状态、进展、旧编辑命令兼容、清除分类、严格校验及日期格式，并验证候选不进入聚合、编辑不丢纳入字段。

`tests/workbench-action-selection.test.ts` 覆盖批量加入待办、重复与空 ID、超限、缺失 ID、整批原子失败、重复提交无变化、撤回限制、候选不能执行，以及普通 `action` 命令无法改变纳入状态或覆盖执行状态。`tests/workbench-pending-edit.test.ts` 覆盖编辑草稿与已保存行动的差异判定（未保存编辑的拦截依据）；`tests/workbench-prompts.test.ts` 保证行动审核输入随 todo / done / dropped 变化且分区正确；`tests/workbench-execution-load.test.ts` 覆盖 A-5 的计数与“移回候选”引导文案。

真实 Electron IPC + 独立 SQLite 验证双来源读写；内置浏览器加载实际生产 React 组件，通过仅用于预览的本地桥连接同一个独立数据库，验证切换、详情、分类、进展、完成与恢复、待办计数、添加和筛选。预览桥、测试数据库与示例数据位于被忽略的 `.codegen/actions*`，不进入生产代码。

## AI 自动分类

Todo 侧栏待归类下方新增 AI 自动分类按钮；四象限的待归类提示条同步提供入口。仅处理当前来源与搜索范围内未完成、未分类的行动，每次最多 200 条。使用当前模型配置，结合来源问题、目的、验收标准、截止日与当前日期分类，写回原问题并更新数量。候选策略不参与分类，因为聚合入口本身只投影已纳入的行动。

主进程按问题分组、每批最多 40 条请求模型，严格检查返回 id 和象限。等待期间被手动分类、完成、删除、移回候选或修改判断依据的任务会跳过，无关进展会保留。失败任务保留待归类，显示结果数量和错误。模型调用记录在 AI 用量中的“行动自动分类”。

验证：全部自动化测试、类型检查、架构检查和构建通过。浏览器使用真实 Electron IPC/SQLite 和本地模拟模型端点验证完整调用与保存链路，未使用真实供应商评估分类质量。
