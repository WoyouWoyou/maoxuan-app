## 1. 结论与建议范围

可以在现有应用中支持其他书籍，沿用「明确问题 → 阅读原文并写感受 → 联系自身 → 反复应用」。主要改造在书籍导入、数据归属、AI 推荐与提示词；阅读、感悟、行动及版本记录可复用。

第一版建议：

- 支持本地导入 EPUB 和 TXT；“equp”按 EPUB 理解。
- 每个阅读问题绑定一本书，新建时选择，可选择内置毛选或已导入书籍。
- 毛选保留专用提示词、核心篇目和示例；其他书使用通用问题式阅读。
- AI 从当前书的真实章节和正文候选中推荐 1–3 个阅读单元；用户可以自行选择。
- 创建阅读问题时即绑定书籍版本；未提交的创建表单允许换书，创建后需要换书则复制问题创建新会话，避免后台请求及已有感悟的来源变化。
- 毛选工作台继续使用其专用框架，第一版仅扩展阅读法。

第一版暂不包含多书联合分析、PDF/OCR、联网找书、DRM 解密或完整 EPUB 排版还原。小说等可支持阅读和反思，但不能承诺每本书都能为现实问题提供直接方法；允许推荐结果为空。

## 3. 用户流程

书架 → 导入文件 → 检查书名、作者、编码及目录预览 → 确认导入 → 可开始手动阅读。

新建阅读问题 → 选择一本书 → 输入问题、背景、尝试 → AI 澄清问题并推荐阅读 → 打开原文并随手写感受 → 写「读到了什么、和我有什么关系、准备尝试什么」→ 实际行动、记录结果、回来复盘。

推荐卡显示章节路径、为什么与用户问题相关、一个带读问题和可点击的原文依据。无正式章节的 TXT 显示「阅读片段 1」等真实生成单元，不把自动切块伪装成原书目录。

导入解析不依赖 API Key。AI 索引可在确认导入后后台准备，展示进度、取消和重试；索引未完成时保留目录阅读和手动选章。首次使用 AI 前说明会向用户配置的服务发送问题及相关书籍片段。

导入确认不自动启动整本书的付费 AI 索引；提供预估及「准备 AI 推荐」入口，由用户显式启动。新建问题需要索引时显示准备状态和选择，短书可走受预算限制的直接推荐。切换页面后任务继续运行，返回页面时读取状态快照，不能依赖组件一直挂载或完整接收到进度事件。

## 4. 文件导入

### EPUB

遵循容器入口 container.xml 查找 OPF，读取元数据、manifest、spine；结合 EPUB 3 导航目录或 EPUB 2 NCX 提取层级及锚点。spine 负责阅读顺序，目录负责章节展示，不能简单假定一个 XHTML 文件就是一章。

第一版转成干净正文，保留标题、段落、列表和引用，图片保留占位说明；复杂公式、图表和固定版式内容给出导入提示。剔除脚本和活动内容，限制压缩包解压体积与文件数量，限制路径范围，检测无法提取正文的文件并明确报错。导入任务放后台执行，避免阻塞 Electron 主线程。

### TXT

优先识别 BOM 与严格 UTF-8，补充 GB18030/GBK、UTF-16；无法可靠判断时让用户在预览中选择编码。中文旧编码能否直接用 TextDecoder 要以打包后的 Electron 环境验证，必要时增加编码库。

识别「第 X 章/节」「Chapter X」等标题，结合正文顺序和长度避免把目录列表当正文。无目录时按自然段分成有长度限制的阅读片段。自动生成的标题与真实标题区分展示，最终确认前可以调整划分。文本规范化一次完成，再生成稳定段落 ID；后续阅读和索引不得改变源段落顺序。

## 5. AI 如何选章节

原则：先检索真实内容，再让 AI 挑选；不要让模型凭书名回忆目录，也不要每次把整本书发出去。

建议第一版流水线：

1. 导入后本地划分检索块，记录所属章节、段落 ID、顺序与源位置；检索块可以重叠，但源段落不重复保存。
2. 对每块可选生成短摘要与主题词，再汇总章节索引；所有摘要带源位置，可缓存、暂停和续跑。长章节不能只取开头作为摘要依据。
3. 用户输入问题后提取多个检索方向，在本书范围内用已有 SQLite FTS5 检索正文与索引。结合目录语义候选，兼顾同义表达；不要仅根据标题匹配。
4. 为候选章节取与问题相关的正文片段，让 AI 重新排序并返回 1–3 个真实 ID、理由、带读问题及证据定位。
5. 主进程验证 ID 属于当前书及版本，引文确实出现在指定段落，证据能支持理由；非法结果剔除。证据与问题的语义关联仍需样例评估，单纯字符串匹配不能保证推荐正确。
6. 找不到合适内容就明确提示，并允许手动浏览；可提供低相关候选但应标注局限，不能硬凑推荐。

章节少且正文短的书可走简化路径，直接将限定预算内的真实文本交给模型。大书使用分层索引，按章节逐步处理；预算以模型 token 限制为准，不能只沿用当前 60,000 字符常量。

SQLite FTS5 先复用，不必首版新增向量服务。它对字面匹配有效，但中文抽象问题与书中用词不同会漏检；如果评估证明语义召回不足，再增加可配置 embedding 与混合检索。不能将基础关键词检索描述成可靠的语义搜索。

成本应在试验中测量：记录每本书索引输入/输出 token、首次推荐耗时和复盘耗时；摘要按文本 hash、prompt 版本和模型配置缓存。索引是一笔单独成本，非免费本地功能；用户改问题时无需重新索引全文。

通用提示词重点是用户目标、现实约束、已做尝试和可验证行动。保留原文阅读与用户自行思考，但不强制套「主要矛盾」「起步/相持/反攻」或要求全书提供同一种方法。书籍正文只作为参考材料，正文中的指令不能覆盖应用指令。

## 6. 数据与兼容性

建议结构：

- books：书名、作者、来源类型、导入时间、隐藏状态、readingProfile（maoxuan/generic）。
- book_revisions：书籍 ID、文件 hash、解析器版本、编码和 immutable 内容版本。
- chapters：全局唯一 ID、书籍版本 ID、父章节、顺序、真实目录路径和源位置；可先扩展现有 articles 表作为章节表，减少第一版改动。
- paragraphs：稳定 ID、章节 ID、顺序、正文和源位置；兼容现有段落数组接口。
- chunks/index：检索块及对应段落范围、摘要和索引版本；可重建，不是原文真相来源。
- sessions：bookId、bookRevisionId、readingProfile、profileVersion、stateVersion；版本快照保存书籍和策略上下文。
- task_runs/task_items：导入、索引、推荐等任务状态、步骤检查点及失败记录，与阅读进度分开。
- model_call_attempts：每次实际模型调用的 Token、来源、状态、配置快照和任务归属；索引页按 runId 查询聚合，不在多处重复累加用量。
- model_configs/settings：模型服务配置、默认用途映射与超时；凭据由主进程凭据存储管理，运行快照不包含密钥。

迁移时把现有文章关联内置毛选，保留 Section0215 等旧 ID；旧会话、版本、消息、行动和感悟默认补齐毛选归属。已有段落下标迁移为相同源段落 ID，不能重新切分后直接沿用下标。

重复文件按 hash 去重；同名书不同文件可并存。重导入不同内容创建新版本，已有会话继续引用旧版本。删除先从书架隐藏；有会话引用的正文继续保留，真正清除需明确处理关联数据。内置书更新按版本和 hash 同步，不再按全库篇数决定覆盖。

AI 与书籍服务由主进程加载会话书籍上下文，不信任前端传入的 bookId。列表搜索、推荐、重读、聊天和读取原文均限制在当前书籍版本。

数据库继续采用现有 better-sqlite3，按模块拆 repository，迁移使用版本序号和事务；不为对齐 EasyPPT 强行更换 Drizzle/libSQL。规范化正文、引用和会话历史保存在 SQLite，以便原子更新；原始导入文件可作为可选归档附件，但不是阅读必须依赖的外部路径。若保存归档，使用应用管理目录、hash 与完整性状态，不能把临时路径或用户源文件路径当长期来源。

首次迁移前备份旧库，失败回滚且不标记成功。迁移后保留旧 ID 映射及旧版本恢复；恢复历史版本不隐式切换书籍或使用新版正文。应用备份需要同时覆盖数据库及选择保留的附件，不能宣称仅备份其中一项就是完整备份。

## 7. 分阶段实施计划

| 阶段 | 交付内容 | 完成标准 |
| --- | --- | --- |
| 0. 契约与样书验证 | 定稿来源/任务/模型契约、选至少 3 类样书、本地验证解析和候选质量；建立固定问题—章节评估集 | 明确章节切分和引用规则；AI 试验走最小统一调用入口并记录用量，禁止新增旁路 fetch |
| 1. 模型与用量底座 | model-runtime、模型配置及快照、结构化错误、唯一重试入口、JSON/流式 usage、调用账本与基础用量查询；迁移现有阅读/工作台/连接测试 | 所有真实请求计量；缺失/估算可区分；重试不双记；取消有效；配置变化不污染在途请求 |
| 2. 书籍与会话边界 | 来源版本、段落定位、旧库备份与迁移、内置书独立同步、reading profile、会话命令与并发校验、按域拆 IPC | 原毛选行为正常，历史感悟及版本来源不变；跨书 ID 被拒绝；失败迁移可回滚 |
| 3. 导入与任务底座 | EPUB/TXT 后台解析与预览、持久化 run/item、排队/取消/恢复、书架与选书、前端按域 store/hooks | 无 Key 可导入及阅读；跳路由/刷新后可恢复进度；重启中断不伪装成功；取消前后均不发布半本书 |
| 4. 索引与通用四步 | 分块索引、缓存/续跑、检索排序、真实引文验证、generic 全流程、消息作用域、按书籍/问题/用途用量页 | 推荐可定位且可为空；索引失败可手动阅读；历史聊天不跨书污染；付费索引由用户显式启动 |
| 5. 清理与发布 | 移除迁移范围内旧 facade/旁路请求、依赖边界检查、质量/性能/故障回归、Mac/Windows 安装包 | 无循环及非法依赖；样书四步完整走通；旧功能回归；安装包内导入、任务恢复和用量均可用 |

质量验收重点：

- 所有推荐 ID、引用和重读建议可定位到当前书的真实原文，伪造 ID 与引文必须拒绝。
- 用少量人工标注的问题—章节样例比较推荐与基线；专门测试没有合适章节的情况，不用模型自评代替人工判断。
- EPUB 包含嵌套目录、锚点拆章、多文件一章、缺少目录；TXT 包含旧编码、无标题、长段落、目录重复。
- 大文件、损坏文件、重复导入、AI 超时、中断续跑；后台导入和索引期间界面可交互。
- 切换问题、版本恢复、移入回收站、书籍隐藏均保持原文和感悟对应；现有毛选阅读法与工作台回归正常。

这属于中等规模功能扩展。工期主要受目录清洗、旧数据迁移及推荐质量影响，建议完成阶段 0 后再给更可靠的时间估算。

## 8. 参考 EasyPPT 后确定的应用架构

### 8.1 对照与采用边界

| EasyPPT 机制及源码证据 | 本项目采用方式 | 适配限制 |
| --- | --- | --- |
| `ipc/index.ts` 按 session/generation/io/config 注册 handlers | library/importing/reading/tasks/models/usage/workbench 分组，handler 校验参数后调用用例 | 不将业务编排继续放入 ipc 目录，不把所有能力塞入一个共享 context |
| `ipc/generation/context.ts` 汇集会话、模型及风格快照 | 任务创建时固定 BookScope、profileVersion、模型配置、promptVersion 和问题版本 | 书籍上下文与运行凭据分开，配置解析不顺带创建任务；可测试且副作用明确 |
| `generation/job-manager.ts` 有排队、reservation、并发限制、取消和中断处理 | 同一资源任务去重、持久化状态、有界并发、AbortSignal 和统一收尾 | 队列记录不等于重启续跑；本项目须额外保存检查点并验证恢复条件 |
| `ipc/context.ts` 进度事件及状态快照；generate:state/listActive | tasks.get/listActive/onEvent，状态是事实，事件负责通知 | 不照搬 500 条事件和 30 分钟 TTL 常量；前端不能以事件流替代持久状态 |
| `io/document-parse-handlers.ts` 资料准备、目录扫描、批次摘要；thinking/context-builder.ts 大资料索引及按需读取 | 本地解析先完成，后续独立索引任务；按目录/检索块读取，摘要带稳定来源 | 现有解析器不直接支持本项目 EPUB；不引入文件自由读写 Agent 或照搬页数/大小阈值 |
| `model-usage.ts` + modelUsageEvents + 用量页面 | 统一模型运行入口与独立 usage 模块，逐次计量及查询聚合 | 补齐书籍/问题/任务归属、失败/取消及未知量，避免全局 DB recorder |
| renderer store、hook 与 IPC client | libraryStore、readingStore、taskStore、usageStore 按域管理共享状态；局部草稿留组件 | store 是主进程状态的 UI 投影，不成为另一份业务事实；不照搬大而全的 sessionDetailStore |
| DB schema/patch、会话风格快照与版本历史 | 版本化迁移、不可变书籍/策略上下文、SQLite 会话快照 | 原文不是可编辑 HTML 作品，不引入每本书 Git 仓库，也不照搬其存储栈 |

目标是“共享执行能力，分离业务规则”。毛选作为专用阅读策略，上传的新书默认 generic；单纯增加一本书不需要开发新策略。

### 8.2 会话、任务、请求和版本必须分开

| 标识 | 含义 | 生命周期 |
| --- | --- | --- |
| sessionId | 围绕一本书讨论的一个问题 | 多次阅读、实践和复盘长期存在 |
| bookRevisionId | 规范化正文的不可变版本 | 只要有当前或历史记录引用就保留 |
| operationId | 一次用户操作及其幂等键 | 可包含多个后台任务或请求 |
| runId / itemId | 一次任务及其中一块索引等子项 | 持久化排队、执行、结果和检查点 |
| attemptId | 一次真实模型请求 | 重试产生新 ID，逐次计量 |
| stateVersion | 会话并发写入版本 | 用户状态每次变更递增 |
| versionNo | 用户可见的阅读历史快照 | 仅关键操作生成，不能拿来替代并发锁 |

主进程保存正式状态和业务规则；后台执行器保存活跃 controller、并发槽和临时进度；React store 保存查询投影、当前选章及弹窗等交互状态。不得用会话的 currentStep 表示索引任务完成，也不能用模型 HTTP 200 表示推荐通过引用校验。

### 8.3 目录与通信契约

采用架构文档中的模块化单体目录：main/modules 下的 library、importing、retrieval、reading/profiles、model-runtime、usage、workbench；SQLite、模型协议、Electron 在 adapters；bootstrap 负责组装；shared/contracts 只暴露 DTO、来源和进度协议。tasks 是 importing/retrieval/reading 共用的独立执行能力，其运行生命周期规则不依赖任何阅读策略。

IPC 按功能拆分，首批契约包括：

- library.list/getChapters/getParagraphs/hide，显式携带书籍版本或由会话推导范围。
- importing.preview/confirm，返回 previewId/runId，不接受 UI 自行提供任意已解析正文写库。
- reading.create/addReflection/saveNotes/applyDiagnosis/recordActionResult，带 expectedStateVersion；主进程在最新状态上应用命令。
- tasks.get/listActive/cancel/retry/onEvent；生成长任务立即返回 runId，后续读取快照和订阅更新。
- models.list/save/test 和 usage.query；模型查询仅返回脱敏配置，凭据不返回渲染进程。

同一 UI 功能可同时使用查询、命令与事件，不要求每项能力只绑定一种调用方式。IPC 事件至少携带 runId、scope、单调 revision 和状态；忽略过时事件。为避免订阅和首次查询间丢消息，先订阅再读快照，按 revision 合并，检测缺口或重新进入页面时再查询。

### 8.4 任务状态、恢复和一致性

建议任务状态：queued → running → succeeded / failed / cancelled；应用崩溃后将原 running 标记 interrupted。业务质量失败与调度完成分别记录，不能只设 finished。

- 资源锁按冲突范围设置：相同书籍版本及索引版本避免重复构建；同一会话同一问题版本避免重复应用诊断；独立书籍允许有界并发，前台交互与后台索引保留独立配额。
- 入队前取得 reservation，提交任务记录后释放预留；排队中取消和运行中取消都须更新持久状态，并释放占用槽。超时/失败/取消共用可重复执行的收尾，避免占位泄漏。
- 书籍正文确认导入在事务内完整发布；取消发生在提交前则不出现半本书，提交后任务返回真实结果，不把已导入内容伪装为从未存在。
- 索引 item 以书籍版本、源内容 hash、索引器/prompt/模型版本幂等。已成功块复用，失败块单独重试；重启只恢复相同有效输入，不自动重发状态未知的模型请求。
- 推荐结果先作为候选保存，应用前检查问题上下文及书籍版本；过时结果保留状态与用量，不覆盖用户新输入。
- SQLite、附件文件与远程调用没有共同事务。附件先暂存、校验再发布，以任务记录清理孤儿文件；远程请求状态未知时不能宣称回滚费用。

### 8.5 消息上下文与模型配置

参考 EasyPPT 的消息作用域，保留现有阅读会话内文章对话展示语义，逐步补足 bookRevisionId/chapterId。第一版不强行拆出新聊天 UI；主进程上下文构造器选择最近相关对话、当前问题、感悟和当前来源，不能把存过的全部历史自动重放，也不能跨会话或跨书复用对话。

模型能力与阅读策略独立。第一版模型配置仍支持现有 DeepSeek/OpenAI-compatible Chat Completions，保留配置迁移；新增多个命名配置和用途默认选择，运行时冻结配置版本。是否支持 JSON、流式 usage、temperature、thinking 等由能力适配决定。其他协议、OAuth 和 Agent SDK 延后，避免为了仿照 EasyPPT 一次引入全部服务商。

运行层集中取消、重试、超时和 Token 记录；prompt 构造器只负责上下文与输出契约，阅读 profile 只提供专用差异。只有在后续协议需求明确时新增 adapter，不让前端页面判断 provider。

### 8.6 架构完成标准

- 新增格式只改 parser/导入预览，更换模型只改 adapter/设置，新增检索方式只改 retrieval。
- 模块外只能使用 public facade；domain 无 Electron/SQL/HTTP 依赖；无反向依赖和循环依赖。
- 关键用例可用假模型及内存 repository 验证；真实 SQLite 测迁移、事务、版本和并发；真实模型样书评估推荐质量。
- 新任务重进页面可恢复状态、重启可识别中断、事件重复不重复应用结果；Token 统计涵盖失败及重试。
- 所有原毛选功能与工作台仍可使用；旧接口过渡必须写明删除阶段，不能永久两套数据写入规则并存。
