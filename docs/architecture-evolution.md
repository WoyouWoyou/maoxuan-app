# 2026-10-19 架构演进记录

本次保留模块化单体，围绕业务规则归属和数据写入边界完成重构。当前结构和约束以 [ARCHITECTURE.md](../ARCHITECTURE.md) 为准；早期多书设计中的兼容写入口已在本次收窄。

## 已完成

1. 从 session-repository 分离数据库连接、设置适配器及会话业务。sessions 服务拥有原子写入和历史，SQLite repository 仅实现持久化端口；可创建相互隔离的服务实例。
2. 阅读和工作台使用各自命令，主进程应用 reducer。整份 SessionData 的 IPC 写入口关闭；页面、演示及 E2E 脚本迁移到新入口。
3. 写入和恢复统一使用版本及幂等 ID，来源/步骤校验、快照、回执共同提交。生命周期更新也递增并发版本。重复请求和失败回滚有真实 SQLite 回归。
4. AI 生成和适用性判断进入应用用例，IPC 仅校验和传输。不同用途选择自己的输入指纹；支持并行工作台诊断，拒绝修改笔记或讨论后的旧结果。
5. 独立 ReadingProfile 契约；generic 使用中性 analysis 字段。retrieval 仅接收查询上下文，不再耦合整份阅读会话。
6. 正式状态和历史快照使用独立 JSON schemaVersion。保留旧笔记、来源和工作台默认字段的明确迁移，并拒绝未知未来版本。
7. 增加运行时 IPC / 状态 / 建议 schema。主进程重新验证引用内容，避免把 AI 或 renderer 提供的 verified 标记当成事实。
8. 抽取阅读和工作台共用的前端命令队列；旧会话的排队操作不能在切换后写入新会话。
9. 会话摘要独立查询；书籍按 ID 查询；全文索引增量维护。解析继续在 Worker 执行。
10. AST 架构规则覆盖完整源代码，增加规则反例测试和 PR 验证工作流。Electron smoke 扩展至工作台四步和并行三路诊断。

## 兼容与开发注意

- 数据库版本 2 → 3 自动迁移；升级前创建 SQLite 备份。数据 JSON 无版本/1 → 2 在读取和恢复时迁移，写入时保存当前结构。
- `sessions.update` 仅接受元数据，必须传 expectedStateVersion；preload 可生成 mutationId。旧外部脚本需要改用 reading.apply / wb.apply。仓库内脚本已迁移。
- `versions.restore` 必须传用户当前看到的 stateVersion。响应丢失后重试同一操作，复用 mutationId。
- 笔记先保存再请求反馈；生成接口不隐式提交草稿。归档/回收站操作后，旧页面须重新加载才能继续修改。
- generic 的旧诊断术语仅作为历史兼容槽，新增中性内容放 analysis。历史上下文元数据不用于要求重新调用模型才能恢复快照。

## 后续演进的触发条件

- 书库或导入量使主进程延迟明显时，先记录 P95 查询/导入延迟与事件循环延迟，再隔离数据库执行器。当前没有做大规模压测，也未将同步 SQL 包装成“已经后台化”。
- 产品需要同一本书的新版本、跨版本笔记时，再引入独立 book_revisions 和映射用例。现有不可变来源继续保留。
- 产品需要多端同步或多人协作时，独立设计全局标识、删除传播、数据同步和冲突策略；本地乐观锁不等同于同步协议。
- 模块需要在同一进程中多实例运行时，沿用 createSessionService 的显式端口模式迁移其 facade；无需提前引入容器框架。

这些是明确的能力边界，不影响当前本地阅读、检索和工作台沿模块持续扩展。
