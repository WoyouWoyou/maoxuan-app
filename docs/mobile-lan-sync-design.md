# 手机与电脑的局域网同步方案

状态：总体目标设计。Android 与桌面的手动文本同步子集已实施，实际范围及测试边界见 [局域网文本同步联调版](device-sync-v1.md)。扫码、增量日志、附件、成长事件跨端同步等仍待实施。更新：2026-11-02。

本文是 [桌面与移动端总体架构](mobile-overall-architecture.md) 的同步专项设计；跨端运行位置、事务模型、原生适配与实施阶段以总体架构为准。

## 产品目标

Android / iOS 手机与桌面应用在同一可互通的局域网中，直接双向同步数据，无需注册账号或云服务器。电脑可以通过网线接路由器，手机通过 Wi-Fi 连接同一路由器。相同 Wi-Fi 名称不保证设备互通，访客网络、设备隔离、防火墙和 VPN 都可能阻断连接。

两端均以本地数据库运行，离线可读可写；电脑作为同步协调端，不是手机日常使用的前提。第一版支持一台电脑和多台手机；手机间通过该电脑交换数据，不做手机直连或多台电脑共同协调。电脑关机时修改留在手机，重连后同步。

## 使用流程

1. 电脑打开“设置 → 设备同步”，用户开启局域网同步服务。
2. 电脑显示配对二维码，手机从“设备同步 → 连接电脑”扫码。
3. 两端核对设备名称及配对确认信息，电脑确认后建立可信设备关系。
4. 首次同步预览两端的数据量、已有内容和附件大小，默认合并，首次同步前两端各自建立备份。
5. 小体积文本数据默认同步；音频、图片、录音、导入书籍文件按类别选择下载，显示预计空间。
6. 后续手机进入前台且电脑可达时自动同步；用户也可以点“立即同步”。

界面显示：已连接设备、上次成功时间、待上传/下载条数、附件传输进度、冲突数量、失败原因和重试入口。必须区分“文本已同步”和“附件尚未下载”。配对设备可以单独撤销；撤销不删除对方已经持有的数据。

## 同步内容

| 内容 | 默认策略 |
| --- | --- |
| 阅读会话、问题、感悟、行动及其历史 | 双向增量同步；复杂会话以完整聚合为冲突边界 |
| 笔记、日记、文件夹 | 按独立实体同步，保留稳定 ID；不以整个日记库作为覆盖单位 |
| 对话消息 | 稳定消息 ID 去重；与所属会话保持依赖关系；流式生成完成后再提交 |
| 阅读与播放位置 | 每台设备保存自己的位置，并提供“在另一台设备继续” |
| 长征活动、收藏、种植记录 | 按事件 ID 去重；派生进度重新计算；不重复累加奖励 |
| 书籍与正文 | 内置资源用版本/哈希比对；导入书籍的正文及来源标识随依赖同步 |
| 图片、录音、书籍原文件 | 清单随数据同步，文件按需下载 |
| 已生成朗读音频 | 可选从电脑下载，按正文版本、音色和内容哈希复用 |
| 字体大小、主题、下载目录、网络代理 | 各设备独立 |
| 模型密钥、访问令牌、后台任务、临时文件 | 第一版不自动同步；模型密钥在每台设备单独配置 |

共享进度不采用“最大页码/最大播放秒数”，以免用户重读时被强制跳到后面。显示位置时附设备名称，时钟时间仅作提示，不承担冲突裁决。

## 网络与配对

桌面 Electron 主进程提供受限的局域网 HTTPS 服务，只暴露同步和受控资源接口，不暴露 IPC、任意 SQL、文件路径或通用文件读取能力。用户关闭同步服务后停止监听。绑定可用的局域网接口，配对时明确显示目标电脑。

采用每次安装生成的设备身份。二维码包含协议版本、电脑端点、证书指纹及短时有效的一次性高熵配对凭据。手机通过原生网络适配器核对二维码绑定的证书；不在整个应用中关闭 TLS 校验，也不通过明文 HTTP 传输笔记与凭据。凭据一次使用后失效，电脑确认后交换长期设备认证信息。私钥与凭据存储于系统安全存储，认证机制采用成熟库实现并测试。

首次扫码提供直接地址，后续可用 Bonjour/mDNS 找回地址；发现结果只用于定位，连接必须再次验证已配对身份。提供手动填写局域网地址并核对配对信息的备用入口，不把发现广播当成信任来源。二维码更换/过期、请求限流及设备撤销均需实现。

手机使用 Capacitor 原生插件处理发现、证书固定、网络请求与大文件传输，避免依赖 WebView 对自签名证书及跨域请求的行为。iOS 配置局域网用途和必要的 Bonjour 声明；Android 按目标 SDK 实现相应局域网权限。系统权限被拒绝时显示具体恢复入口。

## 增量同步与版本

不直接复制或合并两端 SQLite 文件。增加独立同步协议，将领域实体投影为带版本的记录；通过领域校验导入，不绕过原有会话状态与来源规则。

- 桌面分配本地单调递增的变更序号，手机记录该桌面身份对应的同步游标。设备时间不参与排序。
- 本地写入和待发送队列在同一数据库事务中提交，确保退出后不丢待同步修改。
- 每次修改包含设备 ID、唯一操作 ID、实体 ID、已确认的服务端基础版本及变更载荷。
- 同一操作重复提交返回同一回执；同一 ID 对应不同载荷必须拒绝。
- 尚未上传的连续本地修改可压缩为一份最新候选；已经发出的操作载荷保持不可变，后续编辑排队等待其回执，再基于确认版本生成下一次操作。
- 接收变更、处理待发送状态和保存游标必须原子提交；回执丢失时可安全重试。
- 同步写入不再次生成本地待上传修改，防止回声循环；服务器变更记录保留原始操作和设备来源。
- 手机存在未上传的本地修改时，拉取远端版本先写入远端基线，执行冲突判定，不能直接覆盖本地草稿。

基本一轮：协商协议/数据版本 → 拉取变更 → 合并或登记冲突 → 提交本地修改 → 拉取最终确认结果 → 按需传输附件。电脑按事务提交每项聚合修改，批次返回逐项结果；依赖项采用明确的提交顺序及可重试错误。

现有 `stateVersion` 和 `mutationId` 可用于本地并发及幂等，但两端各自产生的 `stateVersion` 数字不可直接比较。新增独立的协调端修订号、同步基线和操作回执；远端修改进入新的领域导入用例，复用 schema、来源及状态不变量校验。

首次连接使用一致性快照加增量追赶：在固定序号读取快照，分页传送，随后拉取快照之后的日志；接收端在暂存区校验完整后原子启用，不能让分页期间产生的更新遗漏。已有本地修改保留并进入合并流程。若两端是分别创建的记录，不凭标题或正文相似度自动合并。

## 冲突和删除

第一版保守处理，不实现字符级实时协作：

- 修改不同实体时自动合并。
- 同一会话或笔记从同一基础版本产生不同修改时，保存基础版本、手机版本和电脑版本，自动保存为原记录与“同步冲突副本”两份可编辑记录，由用户自行合并或删除；不要求同步时选择覆盖某一方。重复请求复用稳定副本 ID，不重复生成副本。
- 冲突版本保持可导出和可恢复，显示设备来源；不能仅凭“修改时间较晚”覆盖另一方。
- 删除作为带版本的墓碑同步；删除与编辑并发时进入冲突，不静默抹除编辑。
- 墓碑及幂等回执不能按短期时间随意清理。只有相关活跃设备均确认越过安全位置才压缩日志；旧设备被显式退役后，重连必须重新配对及全量对账，并保留其离线修改供检查。
- 不提供普通同步操作中的“一键用手机覆盖电脑”。恢复备份是独立流程，会重建同步身份/纪元，拒绝旧游标并重新对账，避免回滚后序号被误用。

## 书籍与附件

先同步正文版本、段落 ID 和来源依赖，再导入引用它们的会话。原始书籍文件可延后下载，但必须已经获得校验所需的正文与来源元数据。缺失依赖时暂存待处理项，界面明确提示，不丢弃笔记、不伪造来源。

文件用内容哈希作为稳定标识；接收端比对清单，只下载缺失部分，支持断点续传、磁盘空间检查、大小限制及最终哈希校验。下载写临时文件，通过校验后原子提交。附件未到齐时正文仍可显示，并标示附件状态。传输请求只能访问授权清单中的资源，不能把客户端参数直接拼成磁盘路径。

现有 `resources/core-audio/v1` 约 333 MiB，可作为电脑向手机下载的资源池。既有 `.audio` 是带缓存封装的文件，移动端应通过受控导出接口获取可播放音频，或实现兼容解码；不得把缓存文件当 MP3 直接播放。音频与文本数据分队列，文本优先。删除手机的离线副本仅释放该手机空间，不删除电脑源文件。

## 运行边界与恢复

第一版自动同步限定手机前台运行、桌面应用启动且局域网可达。不承诺回家连 Wi-Fi 后在手机后台持续同步；锁屏听书与后台数据同步是两个独立能力。传输暂停、电脑睡眠或 Wi-Fi 切换后保留队列，下次恢复。

所有数据首先保存在本机；同步不是独立备份。提供版本化备份导出和恢复。同步前协商协议、实体 schema 及内容版本，不兼容时提示升级，不能静默降级。多台电脑共享同一数据集、异地云同步和手机直连作为后续能力，不纳入第一版承诺。

## 实施顺序与验收

1. 整理同步实体及稳定 ID；将单行 `journal_state` 拆成可独立同步的笔记/文件夹投影，并与本地写入保持事务一致。
2. 实现纯本地同步引擎，验证双向修改、重复请求、并发冲突、删除、断电恢复和多手机顺序同步。
3. 实现桌面局域网服务、手机原生连接、扫码配对、认证和设备撤销。
4. 接入书籍依赖、文本全量/增量同步和用户冲突处理界面。
5. 接入图片、录音和音频的选择性传输及断点续传。
6. Android / iOS 与 macOS / Windows 真机交叉验证：拒绝权限、地址变化、网络隔离、电脑睡眠、传输中断、磁盘不足、旧版本连接、备份恢复与设备退役。

最低验收：手机离线新增笔记后双向同步成功；电脑和手机并发编辑不丢任一版本；重复同步不重复计入活动或行动；中断重试无重复数据；首次同步期间新增修改不遗漏；手机未配对不能读取任何数据；下载音频后断网可播；任何资源哈希不匹配均不能提交为已下载。
